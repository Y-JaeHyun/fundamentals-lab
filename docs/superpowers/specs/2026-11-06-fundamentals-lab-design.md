# 기초체력 랩 (fundamentals-lab) — 설계

- 작성일: 2026-11-06
- 상태: 초안 v2 — 빌더 검토 반영 (사용자 승인 대기)
- 목업: https://claude.ai/artifact/HucvULAR5iFxGshCebMwuf (기획용 · 버려도 되는 코드)

## 1. 의도와 이유

`ebpf-fundamentals-kr`는 내용이 정확하고 꼼꼼하지만 "시간 내서 앉아야 하는 숙제"처럼 느껴져 손이 잘 가지 않는다. 의지 문제라기보다 시작 문턱이 높다.
그래서 **"5분만 해볼까" 하고 들어갔다가 계속하게 되는** 정적 웹 페이지를 만든다. 페이지에서는 브라우저 안 시뮬레이션과 문제 풀이로 게임처럼 개념을 잡고, 진짜 실행은 기존 코스 저장소 예제로 넘긴다.

이 랩은 앞으로 늘어날 여러 코스(eBPF, 로봇 시스템 기초 체력, 이후 추가 요청분)를 꽂아 넣는 **공통 틀**이다. 사용자 본인의 성장 방향(로봇 시스템 전반 이해)을 위한 개인 프로젝트이며, 본인 → 팀 동료 → GitHub 공개 순으로 쓰인다.

## 2. 전체 그림 (프로그램 단위)

| 순서 | 프로젝트 | 이 문서 범위 |
|---|---|---|
| 1 | **랩 사이트 + eBPF 트랙** — 공통 틀 구축, 기존 eBPF 저장소 내용으로 형식 검증 | ✅ 이 문서 |
| 2 | **로봇 시스템 기초 체력 저장소** — 하나의 저장소로 임베디드 → IoT 통신 → 리눅스 실시간 → ROS2 → 로봇 제어를 한 줄로 이어 감. 시뮬레이터 위주(QEMU, Gazebo 등), 라즈베리파이는 이후 검토 | ❌ 방향만 기록. 1번 완료 후 별도 설계 |
| 3 | 로봇 저장소의 장이 완성될 때마다 랩에 로봇 트랙을 붙임 | ❌ 2번과 함께 |

사용자가 정한 것: 로봇 쪽은 **하나의 저장소로 쭉 이어지게**, **시뮬레이터 위주 + 라즈베리파이 검토**, 실행은 저장소가 담당.

## 3. 목표 / 비목표 / 안티목표

**목표**
- 장 하나를 "5분 만져 보기 → 5분 문제 풀이 → (선택) 진짜로 돌려 보기"의 세 단계로 깰 수 있다.
- 설치·로그인 없이 링크만 열면 바로 시작된다. PC와 폰에서 다 된다.
- 새 코스·새 장을 추가할 때 대부분 **데이터 파일만** 쓰면 된다. 시뮬레이션만 코드로 짠다.
- GitHub Pages로 공개 배포된다.

**비목표**
- 브라우저 안에서 진짜 커널·진짜 ROS2를 돌리는 것. 실제 실행은 저장소의 몫이다.
- 계정, 서버, 랭킹, 기기 간 진행도 동기화.
- 영어 등 다국어.
- 코스 저장소 본문을 랩에 옮겨 싣는 것. 랩은 요약과 링크만 갖는다.

**안티목표 (기술적으로 동작해도 실패로 본다)**
- **사실과 다른 시뮬레이션.** 게임이 "XDP에서 막으면 이렇게 된다"고 보여 줬는데 실제와 다르면 실패다. 코스 저장소의 원칙("실제로 돌려 본 것만 싣는다")을 랩도 따른다.
- **텍스트 교재에 버튼만 붙인 것.** 읽을거리가 길어지면 실패다. 한 화면의 설명은 몇 줄 이내로 두고, 조작이 먼저 나와야 한다.
- 결국 또 손이 안 가는 것. 한 단계가 5분을 넘기면 쪼갠다.

## 4. 사용자가 정한 것

- 형태: **정적 페이지**, 브라우저 안 **시뮬레이션 + 문제 풀이**, 게임처럼 진행. 실제 실행은 각 저장소로 넘긴다.
- 대상: 본인 + 팀 동료 + GitHub 공개(누구나).
- 언어: 한국어.
- 목업의 세 가지 형식(퍼즐형, 시뮬레이션형, 샌드박스형)과 허브 구조가 "나쁘지 않다" → 이 방향으로 진행.
- 로봇 코스는 단일 저장소로 이어지게 한다(2번 프로젝트).

## 5. 구조

### 5.1 화면

- **코스 지도(허브)**: 코스마다 트랙 하나, 칸 하나 = 코스 저장소의 장 하나. 칸 상태는 잠김 없음 / 진행 중 / 완료(세 단계 중 1·2단계 완료 시). 순서는 추천일 뿐 **잠그지 않는다**(아무 칸이나 바로 들어갈 수 있다).
- **장 화면**: 세 단계 탭.
  1. **만져 보기**: 시뮬레이션 또는 인터랙티브 요소. 장에 맞는 게 없으면 생략 가능.
  2. **문제 풀이**: 3~5문제. 오답이면 "왜 틀렸는지"를 실제 동작 기준으로 설명한다(목업의 verifier 퍼즐처럼 "커널이 이번엔 뭐라고 할지"를 보여 주는 식).
  3. **진짜로 돌려 보기**: 저장소 장 링크, 재현 명령어 한 줄, 기대 출력 일부. 완료 판정에 넣지 않는다.
- 해시 라우팅: `#<course>-<chapter>` 형태로 각 장에 링크를 걸 수 있게 한다(코스 저장소 README에서 직접 링크).

### 5.2 게임 형식 (재사용 부품)

| 형식 | 설명 | 목업 예 |
|---|---|---|
| 퍼즐형 | 코드/로그/출력을 보고 원인·해결을 고른다. 선택지마다 결과 피드백 | Verifier 퍼즐 |
| 시뮬레이션형 | 미션을 읽고 위치·방법을 고르면 결과가 애니메이션으로 보인다 | 패킷 hook 고르기 |
| 샌드박스형 | 망가진 시스템을 직접 고쳐 동작시킨다 | ROS2 토픽 배선 |
| 순서 맞추기 | 단계를 올바른 순서로 배치 | (eBPF 01장 파이프라인) |

퍼즐형·순서 맞추기는 데이터만으로 만들 수 있어야 한다. 시뮬레이션형·샌드박스형은 장별 코드 모듈이다.

### 5.4 콘텐츠 정확성 규칙

- 모든 문제·피드백·시뮬레이션 결과에는 **근거 출처**를 단다. 출처는 코스 저장소의 파일 경로(예: `chapters/05-verifier/code/out/run.log`, README 절) + 고정한 커밋 SHA.
- 에러 메시지·명령 출력은 코스 저장소의 실제 실행 결과(`out/*.log` 등)에서 가져온다. 저장소에 없는 동작을 보여 줘야 하면 먼저 저장소에 예제를 추가해 실행으로 확인한 뒤 쓴다.
- 검사 스크립트: 콘텐츠의 출처 경로가 고정 커밋에 실제로 존재하는지 CI에서 확인한다.
- **실측과 추정의 경계 (사용자 결정: 혼합 방식)**
  - **질적 결과는 반드시 실측**: 통과/거부, 어떤 에러 메시지, EPERM vs 타임아웃, 어느 hook에서 보이는지/안 보이는지 등 "결론"에 해당하는 결과는 코스 저장소에서 실제로 실행한 결과만 쓴다. 근거가 없으면 그 선택지·미션을 만들지 않는다.
  - **수치는 실측점 기반 추정 허용**: 유실 개수, 지연, 비용, 재전송 간격처럼 슬라이더로 노는 수치는 실측값을 기준점으로 한 단순 모델로 사이 값을 계산해도 된다. 이때 화면에 **"추정치"** 표시를 두고, 실측 기준점은 따로 구분해 보여 준다(예: 실측점은 진한 점, 추정 구간은 흐린 선).
  - 모델 식과 기준 실측값의 출처는 해당 시뮬레이션 모듈 주석과 콘텐츠 출처란에 남긴다. 실측 범위를 크게 벗어나는 입력은 슬라이더 범위에서 막는다.
  - 커널·sysctl마다 달라지는 값(예: 11장 SYN 재전송 간격)은 "이 환경(kernel 6.17) 기준"이라고 명시한다.

### 5.5 진행도

- 브라우저 `localStorage`에만 저장한다. 실패해도(사생활 보호 모드 등) 페이지는 정상 동작한다.
- 저장 단위: 코스 ID + 장 ID + 단계별 완료 여부 + 문제별 정답 여부.
- 콘텐츠가 바뀌어 문제 ID가 사라져도 깨지지 않게 한다(모르는 ID는 무시).

## 6. 제약

- **정적 사이트만.** 서버·DB·외부 API 없이 GitHub Pages에서 동작한다.
- **공개 저장소.** 회사 관련 내용·내부 경로·사내 코드·토큰은 넣지 않는다(코스 저장소와 같은 규칙).
- 개인 저장소이므로 기준 브랜치는 `main`이다. 전역 규칙의 `proto` 기준은 회사 저장소 전용이며 여기엔 해당 없다.
- 라이트·다크 테마, 폰 폭(약 400px), 키보드 조작, `prefers-reduced-motion`을 지원한다.
- 모든 문서와 화면 문구는 한국어. 용어는 처음 나올 때 `한국어(영어)`로 쓰고, 코스 저장소 GLOSSARY와 맞춘다.
- 저장소 생성·GitHub push·Pages 공개는 외부 게시라 사용자 승인 후 진행한다.

## 8. 2번 프로젝트(로봇 저장소)에 미리 적어 둘 것

- 저장소 하나로 임베디드/MCU → 통신(UART·I2C·CAN, MQTT) → 리눅스 실시간성 → ROS2(노드·토픽·서비스·QoS·tf) → 제어 루프·시뮬레이터 순으로 이어진다는 것이 현재의 가정이다. 정확한 구성은 별도 설계에서 정한다.
- 실행 환경은 시뮬레이터 위주(QEMU 계열, Gazebo 등)이고, 라즈베리파이는 검토 대상이다.
- 저장소 이름은 미정이다. Claude 제안은 `robotics-fundamentals-kr`.
- 형식은 `ebpf-fundamentals-kr`과 같다(장별 README + 실행 가능한 코드 + 실제 실행 결과).
- 장이 완성될 때마다 랩 트랙에 붙인다. 목업의 ROS2 토픽 배선(QoS 충돌, 타입 불일치)이 첫 후보다.
